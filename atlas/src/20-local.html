Before the first run

  1. Install Docker, AWS CLI 2.15 or newer, and jq. scripts/aws-sso-guard.sh refuses to continue without them, because older CLIs have no SSO sessions.
  2. Run make docker-compose-up once. If the precisepk-staging-developer profile is missing, the guard script offers to append it to ~/.aws/config. It never logs you in on its own.
  3. Run aws sso login --profile precisepk-staging-developer. If AWS refuses to issue credentials, your IAM Identity Center permission set has not been assigned. Only an administrator can fix that.
  4. Create a GitHub personal access token with read:packages for the @preciserx org. The Makefile asks for it and saves it in .git-token. It then checks the token against the GitHub packages API.
  5. .env is generated on the first run. Pass reset_env=true to refresh it. The fetch writes to a temporary file and replaces .env only on success. It also refuses values that contain # or a newline, because .env parsers truncate them silently (Makefile:75-84, 279-295).
Your local stack uses real staging AWS

Containers mount ~/.aws and use the staging profile. That means real staging Cognito user pools, and the Analytics worker polls the real SQS queue (PreciseRx-Analytics/src/services/SQS/index.js:11-17). There is no emulator.

How the gateway routes

Each public prefix is rewritten to an internal location and then proxied with the prefix removed. from src/services/nginx/conf.d/*.conf and api_backends.conf.

/main/v1/prediction/dose/output
   → rewrite to /_main/prediction/dose/output   (internal location)
   → proxy_pass http://main_upstream/prediction/dose/output
   → main_upstream = kubernetes.docker.internal:8000   (the host's published port)
Public prefixUpstreamTimeoutsExtras
/main/v1:8000120 snone
/database/v1:8001nginx defaultnone
/databridge/v1:8002nginx defaultInjects an X-API-Key header on five routes: Epic launch and callback, Oracle Health authorization URL and tokens, and Sentri7 tokens.
/analysis/v1:8003120 sA separate /socketio location with WebSocket upgrade headers.
/gen-ai/v1:8004nginx defaultnone
  • nginx proxies through the host's published ports (kubernetes.docker.internal), not the compose network, so a service is reachable only while its port is published.
  • Request bodies are capped at 5 MB (api_gateway.conf).
  • JSON error pages exist in api_json_errors.conf but are commented out, so backend error bodies reach the browser unchanged.
  • Every location forwards X-Real-IP, X-Forwarded-For and X-Forwarded-Proto (RX-3432, forwarding the real client IP).

The frontend reaches this gateway through VITE_SERVER_BASE_URL=http://localhost and the socket path /analysis/v1/socketio (PreciseRx-Web/.env, src/actions/AxiosRequestWrappers/Constants.ts:25-31). The frontend also defines a machine_learning/v1 prefix that no gateway route serves.

Working on PK-Library or Shared-JS locally

The services install published versions from GitHub Packages. To run them against your local checkout:

  1. Start the stack, then run make link-pk-library-js. It builds a musl Linux binary with Docker buildx (PK-Library/scripts/prebuild-linux/) and replaces each container's node_modules/@preciserx/pk-library-js with a symlink to the bind-mounted source. Then it restarts the containers.
  2. Rebuild after each C++ change by running the target again.
  3. Recreate the containers (make docker-compose-up) to return to the published version.

The Makefile uses a direct symlink rather than pnpm link. Its comment explains that pnpm link in these containers often reports "Already up to date" and leaves the published version in place. The pnpm store is also forced onto the container's own filesystem, because a store on the macOS bind mount fails intermittently with EPERM (Makefile:109-128).

Editor and repo tooling

  • .vscode/settings.json points C++ TestMate at src/packages/cpp/PK-Library/build/test/PKLibrary_tst and CMake Tools at the PK-Library source and build directories. The C++ compiler is /opt/homebrew/bin/g++-14, and C++ format-on-save is off.
  • Jest "virtual folders" let the VS Code Jest extension run the Main, Analytics and Databridge suites with pnpm test --, on demand.
  • Python files format with black on save, and Pylance type checking is set to standard.
  • .claude/skills/ holds two Claude Code skills: diagram (Mermaid styling) and fix-dependabot.
  • Dependabot checks npm daily at the root. The pull request template has four sections: Issue, Proposed Changes, Additional Info, and Checklist.
