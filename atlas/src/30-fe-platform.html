Frontend platform

A single-page React app, built by Vite and hosted on AWS Amplify. All state lives in one Redux store, and all HTTP goes through one axios wrapper. Every page under / passes a bootstrap wrapper that loads the user, license and metadata before anything renders.

Boot sequence

  1. index.html loads src/index.tsx. This mounts ChakraProvider with the PrecisePK theme inside a Suspense, and initializes i18next as a side effect.
  2. App.tsx refuses Internet Explorer and cookie-less browsers. It then renders <Provider store> around RouterProvider, and stops the mouse wheel from changing number inputs.
  3. The / layout route is withAuth(PrecisePKWrapper). It refreshes the token on reload, then loads:
    • /main/user/info, which also starts Datadog RUM
    • /database/license/validation
    • /main/metadata
    • /main/status, /user/roles, /user/logout-info and /database/updates in parallel
  4. Version check. If the client version (package.json) doesn't exactly equal the server's, patch included, the user is sent to /login. Frontend and Main releases must therefore be version-locked.
  5. PrecisePKWrapper loads all ~72 translation namespaces, routes by preferred role, starts the idle timer, and reports a Datadog view on each route change.
  6. Each section home (UserHome, AdminHome, IAMHome, AnalyticsHome) is wrapped in withRole. That calls a privilege probe: /main/user, /main/admin or /main/iam.
The client-side role gate never redirects

withRole shows /403 only if the probe throws. The HTTP wrapper resolves null on a 403 instead of throwing, so an unauthorized user sees the page shell. Only the backend's per-request checks protect the data. /analytics is gated by the user probe, not an analytics one. (src/hooks/withRole.tsx:19-44; src/actions/AxiosRequestWrappers/AxiosErrorHandlers.ts:75-77)

State

One store (src/store.ts) with thunks, and with the immutable and serializable checks turned off. Redux DevTools is on in every environment except production, so staging case data, which is PHI, can be inspected there.

Two cross-cutting actions. NEW_PATIENT resets every case slice but keeps profile, settings, analytics and application (with its database reset). USER_LOGOUT resets everything. Both are in src/reducers/RootReducer.ts:62-105.

Autosave. src/middlewares/autosaveMiddleware.ts runs after every action. It compares a snapshot of the tracked inputs before and after. If they changed and autosave is enabled in settings, it schedules a debounced save 5 s later (PATCH /database/patients/cases/save). It skips autosave while importing or saving, after a failed save, when the case is invalid, or while paused.

The HTTP layer

Every call is axiosRequestWrapper({method, server, route, wrapperConfig}, data, axiosConfig, onSuccess, onFailure)(dispatch), defined in src/actions/AxiosRequestWrappers/index.ts.

  • URL. getServerIP() + path.join(serverApiPaths[server], route). getServerIP() hard-codes one host per VITE_ENVIRONMENT (src/utils/utils.ts:40-53). The result is an absolute URL, so the axios baseURL (VITE_SERVER_BASE_URL) is ignored for wrapped calls. It is still used to build the SSO redirect URI.
  • Prefixes. main/, database/, databridge/, analysis/ and machine_learning/, each followed by VITE_SERVER_API_VERSION. That value is the blue-green lane (v1 or v2), set per Amplify branch (RX-3666). No gateway route serves machine_learning.
  • Cookies. Always sent (withCredentials: true). The Accept header asks for version=1.0.
  • Options.
    • retryRequest: up to 5 tries, 3 s apart.
    • customErrorHandler: route errors to the caller.
    • handleSessionErrors: on a 401, refresh and retry.
    • cancelDuplicateRequests: abort an in-flight call with the same method and route.
    • preventNetworkRace: ignore stale responses.
  • Errors.
    • A 401 whose body says ExpiredTokenError triggers POST /main/auth/tokens, throttled to one per 10 s, then a retry.
    • Any other 401 logs out.
    • A 403 records the status and resolves null.
    • A 500 retries.
    • No response shows the "connection failed" overlay.
  • Calls outside the wrapper. The token refresh, the browser-direct FHIR calls to Epic and Oracle Health (Bearer token from a cookie), and the Sentri7 simulator.

Sessions in the browser

  • Password sign-in. POST /main/auth/login. On success the app validates the license and goes to /home. NEW_PASSWORD_REQUIRED opens the first-sign-in form. MFA_REQUIRED hits a no-op break, so the spinner never stops.
  • SSO. The browser goes to the Cognito hosted UI with redirect_uri=${VITE_SERVER_BASE_URL}/main/{lane}/auth/token, and the backend exchanges the code. The request carries no state or PKCE, and redirect_uri isn't URL-encoded.
  • Refresh. Happens on page reload, lazily on an expired-token 401, and from the idle prompt. There is no refresh timer.
  • Idle. 30 minutes, with a prompt 5 minutes before. EHR users are logged out with no prompt, because only the prompt is hidden for them. Each tab keeps its own timer.
  • Logout. POST /main/auth/logout, then a redirect based on /user/logout-info. The client-side logoutUser() also runs localStorage.clear().
  • Roles. /main/user/roles. The client adds settings unless the only role is IAM, and adds IAM whenever admin is present.

Datadog and PHI

What reaches Datadog

RUM is initialized outside development with sessionSampleRate: 100, sessionReplaySampleRate: 100, defaultPrivacyLevel: 'mask-user-input' and trackResources: true (src/utils/DatadogRumUtility.ts:13-33). mask-user-input masks form fields, but other rendered text is recorded unless an element is marked data-dd-privacy="mask". 62 elements in 26 files are marked.

On an Epic or Oracle Health import, the FHIR Patient resource is sent as a Datadog action after R4Patient.prepareLogs. That function redacts the name only, and keeps birthDate, identifier (MRN), gender, race extensions and managingOrganization (src/models/R4/R4Patient.ts:307-342; sent at src/actions/EpicActions.ts:148-150). Observation and medication logs keep values, dates, order identifiers and free-text notes.

Whether a Datadog BAA covers this isn't in the code. Ask the compliance owner.

Real-time

The only Socket.IO client is created in src/components/Analytics/ModelAnalytics/ModelAnalytics.tsx:49-73.

  • Connection. It connects to ${VITE_ANALYTICS_SOCKET_ENDPOINT}/serum-analysis using polling only, with credentials. The path is /analysis/{lane}/socketio locally and /socketio/{lane} when deployed.
  • Token update handler. A token:update_usertoken handler writes to socket.auth.token. No auth option is ever passed, so that write would throw if the server ever sent the event.
  • Unused context. SocketContext is declared but never provided.

Translations

i18next loads /locales/{lng}/{ns}.json over HTTP and falls back to English. English has 71 namespaces (72 with the RX-3699 demo). Spanish, Korean, Thai and Chinese have 54 each, missing the same 19. Those include Advanced Analytics, protocol settings and the external-platform wizard, which appear in English for those users. The language is detected from the query string, cookie, localStorage or browser, and switched in General Settings.
