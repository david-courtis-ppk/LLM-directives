The clinical workflow

The pharmacist's path through the app: find or create a patient, enter demographics and labs, choose drug, route and model, enter doses and levels, look at the fitted curve, get a recommended regimen, and save. Each step writes to Redux, and most steps call Main to recalculate.

PatientInformation/Patient card (name, birthday, ID, sex, weight, height, site); Drug card (drug, route, drug factors, amputations, covariates); Lab Results (SCr or measured CrCl, history dialogs, AKI badge); Models; the PK parameter table; renal and body-composition results.
DrugMonitoring/Therapeutic Target, the concentration graph, dose, level and dialysis histories, and the RX-3699 model fit demo.

The Drug Monitoring graph

The concentration graph is drawn with D3 v7, not Chart.js (DrugMonitoring/SerumLevelGraph/SerumLevelGraph.tsx, 2,637 lines). The fit-and-plot response is mapped like this (src/actions/GraphingActions.ts:210-291):

Response fieldWhere it goes
graphic_analysis.bayes_prior_graph, fitted_graphgraphing.bayes_prior_graph and graphing.bayes_post_graph: y, critical points, individual doses.
graphic_analysis.sharedgraphing.shared: sample step dt, axis, hours graphed, graph points and serum levels. Times are converted from UTC to local.
bayes_prior_params, fitted_paramsPK parameters. The individual fit is cleared if too few levels are in use.
covariancegraphing.covariance, which is sent back with Therapeutic Target requests. Its prior half is all zeros (engine issue).
fitting_sessiongraphing.fitting_diagnostics, which the model fit demo reads.
cl_rrt_history, warningsDialysis clearance history; Drug Monitoring alerts.

The graph draws both curves plus an overview strip for zooming, measured levels as squares, critical points as diamonds, the therapeutic band and toxic lines, AUC shading, crosshairs, and a linear or log axis. The on-screen AUC is computed in the browser as sum(y) × dt × auc_conversion.

Fitting settings dialog (the gear icon):

  • Standard error 0.01–0.2, fixed error 0–100, and time weight 1.005–1.01.
  • Objective function: Sheiner 1972 or least squares.
  • A peak-time override for IV routes.

Saving runs fit-and-plot straight away.

RX-3699: the model fit demo

Work in progress on branch rx-3699-model-fit-demo, not yet merged: 5 new files in DrugMonitoring/ModelFitDemo/, 2 test files with 13 cases, the model_fit_demo namespace, and a card rendered below Dialysis History. The card appears when Vite runs in dev mode or VITE_ENABLE_MODEL_FIT_DEMO=true. It has no role or license check.

  • Rating. The card rates the fit already on screen as Good, Check or Poor, without making any new calls. It reads the engine's final residuals (fitting_session.iterations[].loss_j) and partialDerivative.
  • What-ifs. Controls for a level's value (× 0.3 to 3) and draw time (±180 min), the clearance prior SD (5–100%), the prior shape (model, normal, log-normal), and measurement error × 1–3.
  • What-if requests. Each what-if sends its own fit-and-plot request, one at a time, without touching the case, so it can't trigger autosave. The prior-shape control sets fitting_settings.prior_scale. That only has an effect against a local PK-Library build (see the engine side).

J = Jy + Jθ, Jy = Σi εi², Jθ = Σj zj², p = Pr(χ²N ≥ J)

where

εi
the engine's weighted residual for level i, (ŷi − yi) / si, as defined in How a fit works
zj
the engine's prior penalty for parameter j
Jy, Jθ
the part of the objective from missing the levels, and the part from moving away from the prior
N
the number of levels that carry evidence (a zero-residual level at time 0 is excluded)
p
the probability of an objective at least this large if the model and error assumptions hold
A, B
the slopes of the level residuals and of the prior penalties with respect to the parameters, from partialDerivative
Cθ
(BᵀB)⁻¹, the prior covariance of the parameters
κi
the eigenvalues of I + A Cθ Aᵀ, where I is the identity. Jy is tested as a chi-square weighted by 1/κi, and Jθ by 1 − 1/κi. Each uses a Satterthwaite approximation, and the two tests split the false-alarm budget (Šidák correction).

ModelFitDemo/fitMetrics.ts, fitStatistics.ts

Findings in the demo
  • Good with neither check run. With two or more levels and no partialDerivative in the response, the residuals don't count as uninformative, yet both checks return not_judged. RATING_FOR['pass'] then yields Good (fitMetrics.ts:234-260).
  • Silent failures. A what-if request that fails falls back to the base fit, with no message.
  • Least-squares mode. The engine's SD is then 1% of the observed level, so the chi-square premise probably doesn't hold. The code doesn't treat this mode differently.
  • Extra fit requests. The hook subscribes to the whole graphing slice, and the effect that starts fits depends on it. So while a what-if is active, zooming or selecting points on the graph starts another fit.
  • Settings out of range. The measurement-error multiplier can push the standard error beyond the dialog's own maximum (0.2 × 3 = 0.6).
  • Untested code. useModelFitDemo (request building and queueing) and the card have no tests.

Save, autosave and load

  • PUT or PATCH. A manual save, a new case, or a case not yet saved in UTC sends PUT with the whole case. Autosave on an existing UTC case sends PATCH with only what changed, compared against last_saved_inputs over 48 input paths and 4 history paths (src/utils/SaveUtility.ts:20-295).
  • What counts as saved. After a successful save, last_saved_inputs is set to the inputs as they were when the save began. Edits made during the save therefore still count as unsaved.
  • Loading. Loading a case resets eight slices, loads the saved case, asks Main to rebuild everything that isn't stored, then picks the model and recomputes PK. Unsaved changes on the current case are discarded without asking.
  • Duplicate patients. The client has no duplicate-patient check. Database merges patients with identical demographics on PUT.
A failed save is never detected

saveCase sets the status to SAVING and only ever moves it to CONFIRMATION and DONE on success (src/actions/ApplicationActions.ts:254-285). The only code that sets FAILED waits for an error on the route database/${version}/save_patient_and_case_info (src/components/User/Save/SaveContainer.tsx:177-181). But saveCase sends to /patients/cases/save, so that check never matches. After one failed save the status stays at "saving". Manual save then returns early (SaveContainer.tsx:108-111), and autosave skips while the status is "saving". Nothing tells the pharmacist that their work is no longer being saved.

The first note on an unsaved case goes to case −1

handleAddNote saves the case first when caseNum === -1, but then builds the note with the same caseNum, which is still −1 (src/components/User/Notes/Notes.tsx:175-189).

Units and validation

  • Weight and height units. The only options are ['kg','lb'] and ['cm','in'] (src/components/GlobalVariables.ts:164-172), and these strings are sent as-is. That's the only thing keeping the engine's silent kg fallback from firing, because Main accepts any string. A constant LBS = 'lbs' sits right next to them and is used only in tooltip text. It must never be sent.
  • Two conversion factors. kg ↔ lb uses 2.2046 when toggling units, but 0.4535924 in weight-based dosing.
  • Units by value type. SCr values carry no unit; the global creatinine unit setting applies, and changing it converts every entry by 88.42. Dose, level and interval units come from drug metadata, and intervals are stored in hours.
  • Case validity. A case is valid (hasValidCase) only with a valid birthday, PK parameters, CrCl above 0, a model, weight and height, drug information and fitting settings. Navigation, Save, Notes and autosave all depend on it.
  • PK check too permissive. validatePKParameters returns validOthers || validF, so a valid F alone passes, although its comment says every entry must be valid.

Reports, tours, formulas

  • Reports. "Export Patient Report" re-runs fit-and-plot if needed, renders the D3 graph, converts it to a PNG with Canvg, and prints with react-to-print. Both the PDF title and the text export are named ${first_name}_${last_name}_Report, so the file name carries PHI.
  • Tours. react-joyride runs on Patient Home and Drug Monitoring. The automatic first-time tour is commented out.
  • Formulas. Shared/Citation.tsx renders PK-Library's citation objects (equation, variables, factors, sources) with KaTeX. Citations appear on PK parameters (with a Sanford Guide link), CrCl, GFR, body composition and SCr entries.

Other bugs in this area

  • Dose rounding. If the backend omits dosage_increment, doses round to steps of 5 drug units with only a console message (TherapeuticTargetLibrary.tsx:783-808).
  • Graph SVG and DOM.
    • SerumLevelGraph.tsx:1619 writes 'url(#graph_clip' without the closing parenthesis, so individual AUC shading isn't clipped.
    • Each redraw adds a tooltip div to <body> that is never removed.
    • Page-wide D3 selectors can interfere with the report graph when both are mounted.
  • Action creators called without dispatch. The route fix-up in DosageEntry.tsx:249 and getDrugs() in Patient.tsx therefore do nothing.
  • Spinners that don't wait. getBodyComp and getRenalParameters don't return their promise, so their spinners stop after 300 ms whether or not the call finished.
  • Blank tooltip. RangedInput.tsx:82 passes src to Latex, whose prop is source, so the parameter name in that tooltip is blank.
