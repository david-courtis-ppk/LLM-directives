Analytics, Admin and IAM screens

Three sections that clinicians switch to from the app switcher. Each appears in the switcher only for the matching role: analytics, admin or IAM. The route guard behind each one never redirects (see Boot), so the backend is what actually protects them.

Analytics

ScreenShowsCalls
Advanced AnalyticsFilters: drug, route, target, sex, age, CrCl, AKI, drug factors, sites. Three cards: Therapeutic Status Overview, Therapeutic Target Insights (box plots from quartiles the server precomputes), and AKI Analytics. Clicking any chart opens a patient list, then a summary.5 parallel POST /analysis/therapeutic-status/analysis calls (current window plus 1, 3, 6 and 12 months back); GET …/patients/cases/:caseNum/summary. The /aki-analysis/* routes are never called; AKI charts are rebuilt from the analysis response.

The client polls with serum:monitor every 5 s and times out at 15 s. It also calls Database /analytics/cases/count and /analytics/serum/metrics, and Main /pharmacokinetics/models.
Therapeutic SettingsDefault analytics target ranges per drug. The button is admin-only; the route isn't.PATCH /database/admin/settings/therapeutic-settings
  • Effect of the backend broadcast bug. The serum:failed_job handler replaces the matching job by serum_id unconditionally, and doesn't check which query it belongs to. Combined with the Analytics server's broadcast (see Analytics), another user's job with an overlapping serum ID overwrites this user's result. That can turn a good point into a failure and change the statistics after they're on screen. Other users' results with no matching ID are dropped silently, but they have already reached the browser.
  • NRMSD doesn't match its displayed formula. The code computes √MSE ÷ mean(observed) (…/utils/calculateStatistics.ts:109-119). The formula shown to users is √(Σ(O − P)² / Σ(O − Ō)²) (SerumPredictionStatistics.tsx:54). Those are different statistics, so the number doesn't match its own definition.
  • Other issues.
    • The axes stop at 40, but levels above 40 still count in the statistics.
    • Age in weeks is converted with ÷ 54 instead of ÷ 52.
    • The timeout comment says 60 s, but the code uses 15 s, and the timer isn't cleared on unmount.
    • The site filter is enabled in opposite cases on the two pages. On Model Analytics it's disabled for admins; on Advanced Analytics it's enabled only for admins.

IAM (user administration)

  • The screen. One screen, /iam/user-accounts: summary cards, permission filters, the user table, and overlays for invite, edit role and site, disable, enable, delete, resend invitation and password reset. SSO administrators get a read-only view.
  • Invite.
    • Up to 10 emails. Emails on a different domain need an "Invite anyway".
    • PUT /main/iam/users creates the accounts, then PUT /main/iam/users/groups adds the user group plus the inviting admin's own site group.
    • The email check has no anchors, so any string that contains an email passes.
  • Role change.
    • The UI allows one role per user: admin, user or IAM.
    • Non-role groups (All, analytics, site, site_admin) are kept when the role changes (RX-3582).
    • Because analytics is filtered out of every control, IAM can keep it but can never grant or revoke it.
    • The change is sent as PUT /iam/user/group (add), then DELETE /iam/user/group (remove). The remove request passes the email as username, while test fixtures show usernames are UUIDs. If Main rejects it, a demoted admin keeps the admin group.
  • Disable, enable, delete. Each needs one confirmation, and checks that sub, userPoolId and username are present first (RX-3302). Nothing stops an IAM user from disabling, deleting or demoting their own account.
  • Tests. About 115 across 12 files. This is the best-tested area of the frontend.

EHR import, sign-in and the app shell

When a clinician launches from Epic or Oracle Health, Databridge redirects them to /ehr?provider=…. From there the browser runs a step-by-step import wizard. It reads the EHR token from a cookie, queries FHIR directly, asks Databridge to shape the result into a case, and either creates a new case or syncs an existing one.

The import wizard

  1. Mount. /ehr sits outside the withAuth wrapper, so it has no idle timer and no navigation bar. On mount it resets the case (NEW_PATIENT) and pauses autosave. That stops a stale case from being saved as a duplicate (BLITZ-3.6.0-1). The reset happens even when provider is missing, and in that case the page stays on "connecting" forever.
  2. Connect.
    • Epic: read _epic_access_token, then GET /databridge/ehr/epic/session-info, which returns the issuer, patient FHIR ID, CSN, system login, facility, medication statuses to accept, MAR actions to skip, and the timeline window.
    • Oracle Health: read _o_h_access_token, then GET /ehr/oracle-health/session-info. The token is refreshed through POST /ehr/oracle-health/token when less than 3 minutes remain.
    • Sentri7: GET /sentri7/tokens with x-auth-code (its result isn't checked), then POST /sentri7/data.
  3. Common setup. License validation, metadata, settings, protocol settings, and the user profile (which starts Datadog).
  4. Patient. FHIR Patient/{id}, parsed by src/models/R4/R4Patient.ts. For Epic, the ID shown is the EPI; otherwise it's the MRN, chosen by identifier period. A race extension can add a drug factor, except at one named institution that has opted out.
  5. Match existing cases. POST /database/databridge/case_summary with name, ID and birthday. The backend returns only exact matches.
  6. Choose. The wizard offers three paths:
    • New case: Define Filters (drug, route, timeline; quick picks from 24 h to 30 d), then fetch FHIR.
    • Load an existing case: /cases/load_case only.
    • Sync: fetch over a new timeline, then compare each SCr, CrCl, dose and level entry as current, incoming or matched.
  7. Fetch. Vitals (height, weight), SCr, CrCl and drug levels as Observations, filtered by LOINC codes from /ehr/drug-codes. For doses:
    • Epic: MedicationRequest, then the private MAR API for the matching orders.
    • Oracle Health: MedicationAdministration?status=completed.
    Pagination follows every next link, and the timeline can reach back to 2000-01-01.
  8. Format. POST /databridge/ehr/format-data returns a Redux-shaped case, which the pharmacist reviews in two steps (patient information, then medical information), with per-row checkboxes.
  9. Complete import. Keeps only the checked rows, runs drug information, default settings, PK, renal parameters and AKI assessment (RX-3639), then navigates to /patient-info.
Things to know
  • CrCl field name. Epic parses CrCl into level, while Oracle Health and the UI use value. This is correct only if Databridge maps the Epic field.
  • Private API URL. The Epic private-API URL gets a double slash (…/api//epic/2014/…), and it breaks if the issuer doesn't end exactly in /FHIR/R4.
  • Route codes. Only vancomycin has route codes. Other drugs import only when their route text contains "Intravenous".
  • Idle logout. EHR users are logged out on idle with no prompt.
  • Test coverage. No tests cover EpicActions, OracleHealthActions, EHRActions, the medication parsers, or the wizard's filter and sync steps. Every component fixture is a Sentri7 store.

Sign-in screens

  • LoginWrapper serves /login, /sso-login and /forgot-password. On mount it checks /auth/status. If signed in, it shows "existing session"; otherwise it resets Redux and clears the EHR and Datadog cookies.
  • First sign-in. An invited user sets their name, phone and a new password, sent to /auth/sign-up with the Cognito session.
  • Forgot password. It always moves on to the code step, even when the request failed.
  • Logout for EHR users. Logout doesn't sign EHR users out; it restarts the EHR import instead.
  • Sentri7 simulator. /external-platform-workflow is a fake Sentri7 screen that posts synthetic cases to a hard-coded import URL. It's routed in production.

App shell and shared components

  • Top bar. MainNavigation is the fixed top bar: app switcher, logo, navigation links (disabled while the case is invalid), and the Alerts, Notes, Save, Settings and Account icons.
  • Error handling. ErrorBoundary logs to Datadog and /logs/errors, then checks versions. ConnectionFailed is the reconnect overlay. InvalidEpSession appears after an EHR user refreshes the page.
  • Shared building blocks (src/components/Shared/):
    • a react-table wrapper with search, sort and cursor pagination
    • cross-browser date and time inputs
    • dropdowns and multi-selects
    • the KaTeX Latex component and the Citation popover
    • report preview and export
    • settings panels shared by user and admin
    • warning modals
    • the "what's new" carousel
  • GlobalVariables.ts. 807 lines, imported by 229 files. It holds colours, date formats, cookie names, PK bounds and descriptions, value ranges, unit options, SSO provider lists per environment, and target definitions. Its ISO_8601_STRING format uses sss, which isn't a millisecond token in dayjs, so seconds print twice.

Frontend tests

About 124 files and about 734 cases, run with pnpm test. HTTP is mocked with MSW handlers against http://localhost/{service}/{lane}/…, and component tests render with a real store preloaded from JSON snapshots.

  • Setup. src/setupTests.ts uses jsdom, sets the timezone to America/Los_Angeles, starts the MSW server and stubs a few browser APIs. src/utils/tests/TestsUtility.tsx provides a render that wraps i18n, the router and an error boundary around a real store.
  • How to run. pnpm test watches locally and runs once in CI. pnpm test -- --run runs once. pnpm test -- --run --coverage adds v8 coverage, with no threshold set.
  • Best covered. IAM (~115 cases), Login (~57), Settings (~53), R4 patient parsing (~49), ValidationLibrary (45).
  • Not covered.
    • SaveContainer, saveCase and the PUT/PATCH choice. That is why the failed-save bug above went unnoticed.
    • Autosave outside the EHR page, loadPatientCase, and the fitAndPlot response mapping.
    • The D3 graph, reports, notes and archive.
    • The Model Analytics socket flow and calculateStatistics.
    • The admin protocol manager (639 lines).
    • The EHR fetchers.
  • Mock mismatch. The MSW mock for /auth/logout is a GET; the app sends POST.
