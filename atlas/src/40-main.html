PreciseRx-Main

Main is the API behind every clinical calculation and every sign-in. Each clinical route validates a JSON body and makes one or more synchronous calls into PK-Library. Main also runs Cognito sign-in and the user-administration screens. It stores no patient data.

Middleware order

  1. trust proxy set by private CIDR ranges, so req.ip is the real client (RX-3432). ETags are off.
  2. helmet, with HSTS for one year; the Morgan access log from Shared-JS; CORS for the single origin PPK_CLIENT_URL with credentials; body parsers (2 MB); sanitizeCookies; compression.
  3. Unauthenticated routes: POST /status, GET /HealthCheck, and everything under /auth.
  4. Authentication chain: validateAccessToken → validateIdToken → validateTokenPairing → validateAccountRevocation. A test locks in this order (test/controllers/authentication-chain.test.js).
  5. Routers: /, /admin, /aki, /drug, /iam, /pharmacokinetics, /prediction, /search, /user, /logs. Each adds its own role check.
  6. The shared ErrorHandlerMiddleware. Anything that isn't an ApplicationError becomes a 500.

IAM calls run under the caller's own AWS role, obtained through the Cognito identity pool (src/utils/cognito-utilities.js:31-49). The IAM policy on that role is therefore a second guard, and it isn't in this repo. Rate limits: invites allow 1 per second per caller, and resend-invitation allows 5 per hour per recipient. Both are shared through Redis. The other IAM limits are counted per process.

Validation is advisory

46 controller files call const { value } = validate(…) and ignore the error. validate() logs errors without the value, then returns both, and the handler carries on with whatever came in. Only the IAM and logs handlers reject bad input. (src/utils/validation.js:36-84; prediction/dose/post-output.js:29)

Combined with the engine's error handling, a malformed request can come back as 200 {}. Joi's default message for a failed pattern includes the value, so a malformed birthday could reach the logs next to the username and license.

Tests and build

  • Test setup. Jest 30, supertest and sinon. The token and role middleware is stubbed before the app is required (test/.test-ignore/test_config.js:63-96).
  • The engine is not mocked. Controller tests run the real addon. Most assertions only check for HTTP 200. The three fixtures named amikacin, busulfan and vancomycin are all amikacin with the same patient.
  • Running them. On the host, run GIT_TOKEN=… pnpm install --frozen-lockfile && pnpm test. The dev container doesn't copy test/. CI runs the same on every pull request, with no lint step.
  • Images. Dockerfile is for production, Dockerfile.staging for staging, and Dockerfile.dev for local development, built from the umbrella root.
  • Jenkins. It builds on arm64 and pushes to Docker Hub, tagged with the last segment of the branch name. It runs no tests and has no deploy step.
Production Dockerfile has no package token

Jenkins passes the GitHub Packages token as a BuildKit secret, --secret id=git_token. Dockerfile.staging:20-22 mounts it. Dockerfile:22 runs pnpm install without the mount, so ${GIT_TOKEN} in .npmrc is empty there. The two diverged in commit 44360c3 (RX-3468, 2026-06-24). Production builds may be succeeding only from the build agent's warm pnpm cache.

Other quirks

  • POST /status calls response.status(204) without .send(), so it never responds.
  • The Sentri7 logout check compares against 'SENTRI_7', but the provider value is 'sentri7', so it never matches (get-logout-info.js:64-65).
  • /auth/login returns an MFA_REQUIRED challenge, but no route answers it.
  • The drug package is not enforced on calculations. Any drug name reaches /pharmacokinetics and /prediction.
  • The SSO launch sets the refresh cookie for 1 hour instead of 1 day.
  • sinon and supertest are production dependencies. PPK_MULTI_SITE_ADMIN_ROLE is required at boot and never read.
