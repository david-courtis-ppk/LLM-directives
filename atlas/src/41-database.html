PreciseRx-Database

Database is the data-access API. Patients, cases, doses, levels, PK parameters, notes, settings and the audit trail all live in MySQL, with one schema per customer institution. The service also answers license, SSO and EHR-tenant lookups from a shared licenseinfo schema. The browser calls it directly, and so do Main and Databridge.

What happens on each request

  1. An XSS regex screen on the body and headers.
  2. A session on licenseinfo: the reader endpoint for GET, the writer otherwise (app/middlewares/session.py:66-86).
  3. Token validation, then revocation, then the role check (below).
  4. A session on the tenant schema, named by the institution ID from the user's license (session.py:40-63).
  5. The caller's email is resolved. On first sight it comes from Cognito AdminGetUser, then it is cached for an hour.
  6. After the handler runs: the edit-history audit row (for seven endpoints), session close, and no-cache headers.

Connections. Engines use NullPool, so each request opens at least two fresh MySQL connections. No TLS options are passed to the driver (app/database/engine.py:76-87; no ssl or connect_args anywhere).

Credential rotation. Credentials come from the secret named by RDS_SECRET_ARN and are cached for 60 s. A do_connect hook injects them into every new connection. If MySQL rejects the login with error 1045, the hook re-reads AWSCURRENT uncached and then tries AWSPENDING. That covers the window mid-rotation (engine.py:90-169; secrets.py:89-129).

No migrations or DDL live here, so the ORM is the only description of the schema in this repo. The production schema may differ from it. Tests create tables from the ORM metadata. Ask who owns migrations; a comment points at a License Tool (app/__init__.py:52-54).

How a request finds its schema. The id token's custom:license_name leads to the license, the license to the institution ID, and the ID is the schema name. The mapping is cached for an hour (app/middlewares/validate_token.py:207-221). The license expiry date is parsed from the last word of the license name, as MM-DD-YYYY.

PHI is stored in plain columns. The service does no field-level encryption and makes no KMS calls. Encryption at rest, if any, is at the RDS storage level, which isn't visible here.

Roles come from the cognito:roles claim. cognito:groups is never read, and the analytics and site-admin roles are not enforced here. Nothing in Database restricts a user to their own site within an institution: site filters come from the caller, and cases load by number alone.

Audit trail

An after-request middleware writes an edithistory_web row for seven endpoints: load, create, update, autosave, archive and delete. It does not audit unarchive, moving a case to another site, notes, settings, protocol settings, facility changes, or bulk reads such as POST /cases, /patients and the therapeutic bulk export.

Deleting a case may erase its own history

The audit row's case number is a foreign key with ondelete="CASCADE" (app/models/hospital/edithistory.py:13-17). Deleting a case therefore deletes its audit rows. The DELETE_CASE row is then written for a case that no longer exists. The audit writer wraps everything in a bare except: rollback (app/middlewares/edithistory.py:145-146), so that failure is silent. This is how the ORM defines it; whether the production DDL matches is unknown.

Tests

The test suite drops databases

Fifteen test files use fixtures that drop and recreate the MySQL databases testing, 1683, 1119 and 1401 at root:root@127.0.0.1:3306 (test/conftest.py:29-41, 134-141). Point it only at a disposable local MySQL. pytest-dotenv also loads the nearest .env walking up, which is the umbrella's real one.

  • Run make install-requirements, which injects the token from .git-token. Then make test, or make test k=name to filter.
  • Well covered: token pairing, expiry, revocation, roles, API keys, XSS, proxy fix, engine and secret rotation, IAM routes, protocol validation, analytics queries, PATCH save.
  • Not covered: the audit middleware, admin delete and unarchive, notes, PUT save, the EHR routes.
  • CI starts both a mysql:8.0 service container, with no port mapping, and the runner's own MySQL. The tests most likely hit the latter.

Other quirks

  • Patient search terms (name, MRN, birthday) are GET query parameters, and the gunicorn access log records the raw URI.
  • Tokens can reach the logs. The access-log format includes the Authorization header whenever parsing throws, and an unknown issuer logs the whole JWT (vendor_info.py:64).
  • The Epic tenant route answers an unknown tenant with HTTP status 0 and the body "401" (epic_api.py:128-129).
  • request.json.get("therapeutic_settings" or {}) applies the default to the key, not the result, so a missing key causes a 500 (administrators.py:61-62).
  • JWKS and refresh-token HTTP calls have no timeout, and the server runs one sync worker, so a slow call stalls the whole container.
  • The runtime image carries black, pytest and alembic, and pydantic is unpinned. There are three near-identical Dockerfiles.
