PreciseRx-Databridge

Databridge brings EHR and partner data into PrecisePK. It runs SMART on FHIR launches, where a clinician opens PrecisePK from inside Epic or Oracle Health. On first launch it creates the clinician's Cognito account. It keeps each session's EHR context in Redis, and it converts parsed patient, lab and dose data into PrecisePK's case shape. The browser, not Databridge, reads the FHIR data.

Partners, as the code sees them

PartnerWhat the code does
EpicEHR launch as a confidential client. One EPIC_CLIENT_ID for all customers, with a secret per customer in Secrets Manager (a JSON map from identifier to secret). User identity and encounter context arrive as Epic "Token Library" parameters in the token response. The browser also calls Epic's private GetMedicationAdministrationHistory API.
Oracle HealthEHR launch with online_access, so a refresh token is issued. One client ID and secret for every customer. Databridge uses the token introspection and revocation endpoints.
Sentri7An external platform that POSTs patient, lab and medication JSON to /sentri7/import, authenticated with an authorization code from one of two Cognito pools (V1, V2).
SSOA Cognito pool whose tokens Databridge accepts and checks for revocation. SSO sign-in itself happens in Main.
SolanaOnly env var names. Nothing reads them, and Databridge would reject a Solana token.

Two gaps in this flow

No OAuth state and no PKCE. Neither the Epic nor the Oracle Health authorize redirect includes them (controllers/ehr/epic/get-launch.js:41-48; controllers/ehr/oracle-health/get-authorization-url.js:32-39), and nothing in src/ generates or checks either. SMART App Launch v2.2.0 marks state required, "with at least 122 bits of entropy", and requires PKCE for public and confidential clients alike (hl7.org/fhir/smart-app-launch). STATE_SIGNING_KEY is in .env, but nothing reads it.

The callback uses two identifiers without comparing them. It authenticates the code exchange with the identifier from the URL path, but it provisions the account against the identifier from Epic's token response (get-callback.js:165-182). The risk is a misconfigured customer placing users in the wrong institution, not an outside attacker, because the token response is authenticated.

Account details on first launch:

  • The username is ${id_token.sub}:${tenantId}, lowercased. The id token is decoded, not verified.
  • The user is added to the institution's All and user groups. Every launch resets custom:license_name and sets a new random 32-character password.
  • Multi-site customers need an encounter-facility NPI or an admin location ID. Databridge creates the facility row and a site group if they are missing, but no code here adds the user to that site group.

The Oracle Health launch

  1. GET /ehr/oracle-health/authorization-url?iss=&launch=. It validates the issuer with Database (exact match, cached 1 h) and discovers the authorize, token, revoke and introspect URLs. It then redirects with scopes online_access launch openid patient/Patient.read patient/Observation.read patient/MedicationAdministration.read.
  2. GET /ehr/oracle-health/tokens?issuer=&code=. It exchanges the code with the single global credential. It then creates or refreshes the Cognito user (${username}-${tenant}) and introspects the token for its expiry.
  3. It stores the encrypted refresh token and session in Redis, and sets _o_h_access_token, which JavaScript can read, plus the Cognito cookies. It redirects to /ehr?provider=oracle-health. The error path redirects to the same URL.
  4. The browser calls GET /ehr/oracle-health/session-info, and refreshes with POST /ehr/oracle-health/token.
  5. When the Redis key expires after an hour, a keyspace subscriber reads the shadow copy and revokes the refresh token at Oracle Health. In production that depends on keyspace notifications being enabled in Valkey.

Sentri7

  1. Sentri7's server calls POST /sentri7/import with x-auth-code and a body of patient, labs and medication. Databridge exchanges the code at the matching Cognito pool.
  2. It stores {importData, tokens} as plain text under the raw auth code for 60 s, and returns redirect_uri=<client>/ehr?provider=sentri7&code=….
  3. The browser calls GET /sentri7/tokens. Databridge sets the Cognito cookies and also returns the tokens in the body. It does not delete the key, so the code can be replayed within the 60 s.
  4. The browser calls POST /sentri7/data, which formats the parked import with the same mappers. It doesn't check that the caller owns the import.

Turning EHR data into a case

POST /ehr/format-data validates patient, labInfo and medicationInfo. It returns {drug_list, non_integrated_drug_list, patient_info: {dosage_histories, drug, patient, serum_histories}} (controllers/ehr/post-format-data.js:55-119).

  • Patient. Age comes from the birthdate, truncated to two decimals. BSA comes from PK-Library. SCr history is converted to the user's unit. CrCl reported per 1.73 m² is converted to mL/min using BSA. Amputation values are standardized.
  • Doses. These are sorted and routes are cleaned. A missing infusion time comes from PK-Library. A missing interval is filled with the gap to the next dose, then the previous dose's interval, then 12 h, capped at 7 days. Continuous infusions become hourly rates. When the infusion time is -1 or 0, the per-hour normalization produces negative or infinite doses.
  • Levels. Creatinine and drug levels, converted to the drug's concentration unit. In production the serum amount-unit list is hard-coded under a // @TODO Delete before release comment.
  • Code lists. /ehr/drug-codes returns RxNorm medication codes (21 drugs) and LOINC lab codes (24 files, 21 imported). The key ValproicAcid doesn't match PK-Library's "Valproic Acid". Valproic acid imports therefore likely get empty code lists.
  • Per-customer rules. Which MAR actions and MedicationRequest statuses count is hard-coded by URL substring for three named health systems, with @todo Move to database tables (epic/get-session-info.js:82-161).

All /ehr and /sentri7 routes are limited to 50 requests per 10 minutes per IP, counted in memory per process. A hospital behind one NAT address shares a single budget. The API key only proves the request passed through the gateway, which injects it. It is compared with ===, while Database uses a constant-time comparison.

  • Encryption. AES-256-CBC with no authentication tag. The key is scryptSync(secret, 'salt', 32), with a fixed salt, recomputed on every call (utilities/crypto-utilities.js:29-98).
  • Cookies. The two EHR access-token cookies are readable by JavaScript, because the browser needs them for FHIR calls. Any XSS on the PrecisePK domain would expose FHIR access.
  • Logs. The access log records full URLs, including OAuth codes and the Epic launch token. Raw axios errors are logged in 13 places and can carry request headers or Basic credentials.
  • Audit. Creating Cognito users, resetting passwords and creating groups or facilities are not audit-logged. The only trail is one access-log line per request.

Tests and debt

  • Test gaps. Jest covers the Sentri7 mappers, import schema, session-info filters, revocation, pairing, trust proxy and IP context. No tests cover the Epic or Oracle Health launch, callback or token controllers, the crypto helpers, the expiry handler, or the API-key check.
  • Dead code. services/fhir/* (never imported); about 755 KB of sample FHIR data containing identifiers, shipped in the production image; unused env vars that are still required at boot.
  • Error handling. Two paths return the wrong status:
    • The multi-site error handler overwrites its own branches, so every error returns 400.
    • HttpStatus.InternalError is undefined, so an internal error returns 400.
  • Misleading names. SENTRI7_REDIS_URL holds all EHR data, and the :issuer route parameter is really the identifier.
