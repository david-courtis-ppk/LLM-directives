How a Bayesian fit works

The fit finds the parameters that best explain the measured levels without straying further from the population prior than the data justify. It uses a hand-written Levenberg-Marquardt optimizer. It doesn't use Nelder-Mead or Eigen.

The objective

J(θ) = Σi [ (ŷi(θ) − yi) / si ]² + Σj zj²

where

θ
the fitted parameters (for Rodvold 1988: CL and Vdβ); θj is the j-th one
J(θ)
the quantity the optimizer minimizes
yi
the i-th measured drug level, mg/L
ŷi(θ)
the level predicted by θ at the same time, mg/L. It is floored near 0.1% of the highest measured level, so the optimizer never divides by a zero prediction.
si
the error scale of level i (next box)
zj
the prior penalty on θj (box after)

The residual functions are That the optimizer sums their squares is from individualfitting.cpp:88-100. Parameters enter the sum as extra pseudo-observations (bayesianfitting.cpp:223-229).

si = max( r tlast − ti · ( σA · ŷi + min(σF, 100 · σA · ŷi) ), 0.01 · yi )

where

σA
proportional assay error. It is standard_error in JavaScript and assay_error in C++. Vancomycin's default is 0.1.
σF
fixed error, mg/L. It is fixed_error in JavaScript and sem in C++. Vancomycin's default is 1.25. The cap of 100 · σA · ŷi stops σF from swamping near-zero predictions, which the code says can trap the fit in a local minimum.
r
time-weight factor, time_weight_factor. Vancomycin's default is 1.005, or 1.01 in ICU. Because r > 1, older levels get a larger si and count for less.
ti
time of level i, hours since the first dose
tlast
time of the latest measured level, hours (max_level_time() returns the latest level's time)

level_loss_v1.0.cpp:11-38 In least-squares mode, σA · ŷi is replaced with 0.01 · yi and σF with 0 (:26-29). Vancomycin defaults are from src/drug/vancomycin.hpp:803-823

normal: zj = (θj − θpop,j) / max(CVj · θpop,j, 0.01 · θpop,j) + ej

log-normal: zj = (ln θj − ln θpop,j) / max(CVj, 0.001) + ej

ej = exp(2 · uj) − 1 if θj < 0.1 · θpop,j, otherwise 0; uj = (0.1 · θpop,j − θj) / (0.1 · θpop,j)

where

θpop,j
the prior (population) value of parameter j
CVj
its prior coefficient of variation, stored in the field named sd (0.5 for Rodvold CL, 0.3 for Vdβ)
ej
an extra penalty that grows as θj falls below a tenth of its prior, keeping parameters away from zero
uj
how far below that tenth θj is, from 0 to 1

param_loss_v1.1.cpp:19-45 Log-normal is used when prior_scale is "lognormal", or when it isn't "normal" and the model is nonlinear (:31-32). The log-normal form divides by CVj directly; the code's own TODO asks whether it should use a log-scale SD instead (:36).

PK-Librarymodel/, math/, doseprediction/, therapeutictarget/

Simulation and dose search

Concentrations come either from a closed-form formula or from a numerical simulation. Regimens come from an analytic formula when the model and target allow it, and from a bracket-and-bisect search otherwise.

Predicting a concentration

PathWhenHow
Closed formThe model is linear, nothing is time-varying, there is no dialysis, and every dose is intermittent IV (model.cpp:730-745).Each dose's analytic contribution is added up. The Eigen-based LinearPK module rebuilds full compartment state from past doses (math/linear_pk.h:7-34).
SimulationEverything else, including oral doses, continuous infusions, dialysis and time-varying CL."basic_euler" by default: a fixed-step explicit Euler loop doing absorption, then distribution, then elimination in each step (pksimulator_euler.cpp:190-231). Steps are 1/120 h or 1/320 h, and 1/9 h for biologics. Runs to 60 days, or 365 for infliximab and adalimumab (pkconstants.cpp:30-38).
Steady stateRegimen forecasts.Its own inline Euler loop, stopping when consecutive troughs agree within 0.01% (model.cpp:805-961).

RK4 and Dormand-Prince simulators exist, but they aren't the default. Their test suites account for most of the 249 disabled tests, and seven Boost-based versions are disabled with a .disabled file extension.

Supported structures: 1-, 2- and 3-compartment linear models, Michaelis-Menten one- and two-compartment models, Erlang transit absorption, lag time, dose-dependent absorption rate, time-varying CL and dialysis clearance.

Finding a regimen

  • Analytic. One-compartment IV trough, peak, AUC, and peak with trough. For AUC, the dose is the per-interval AUC × CL ÷ (F × salt factor) (onecompartment.cpp:512-559). Two-compartment IV AUC is also analytic.
  • Search. Model::target_binary_search brackets the answer by doubling or halving from 250 and 500. It then bisects until the error is within 0.001 target units, up to 200 iterations. Each step simulates the regimen to steady state (model.cpp:336+).
  • Loading dose. Searched separately when the starting level is below 0.95 × the steady-state trough (model.cpp:375-406).
  • Continuous infusion. AUC is converted to a target average concentration of AUC ÷ 24.
  • Trough-range courses. These use a finite loading course plus maintenance (teicoplanin). They use the closed form LinearPK::dose_from_state (linearmodel.cpp:216-301).
  • Cumulative AUC. For 48, 72 or 96 h, the AUC already given is subtracted.
  • Infusion time. Starts at 0.5 h and grows in 0.25 h steps until the institution's protocol is satisfied. The same loop is copied into the binding (pklibraryjs.cpp:2343-2362).
  • Confidence range. Uses finite-difference sensitivities combined with the covariance (the delta method). Only the upper triangle is summed, and the result is about ±1 SD, although it is labelled a 95% interval. The comment says "unable to find source for this algorithm" (steadystate.cpp:175-206).

RX-3699: choosing the prior's scale

RX-3699 is the model-fit and goodness-of-fit work. This branch adds an optional fitting setting, prior_scale, which chooses whether the prior penalty is computed on a normal or a log-normal scale. Gaps before this can ship

  • Nothing calls FittingSettings::is_valid. A typo such as "log_normal" silently behaves like "model". Main's Joi .valid(…) doesn't help either, because Main logs validation errors and carries on (see Main).
  • A value that isn't a string throws inside argument parsing. The engine catches it, so fit_and_plot returns {}.
  • The services pin 1.6.1, which doesn't read prior_scale. The field is ignored everywhere except a container linked to your local build.
  • The package version is still 1.7.0-rx-3240.0, so publish.yml will not publish this work.
  • The log-normal penalty divides by CV directly. The exact log-scale SD for a given CV is √ln(1 + CV²): 0.472 for CV 0.5 and 0.294 for CV 0.3.

PK-LibraryQuirks

Engine risks and technical debt

Items that could affect a dose come first.

Could affect a dose

  • An unexpected weight or height unit silently becomes kg or cm (above).
  • Failures come back as {} or -1, so a caller can't tell "no result" from "failed" except by the response's shape.
  • Declared parameter limits are never applied (Rodvold limits).
  • An unconverged fit is reported as SUCCESS.
  • The returned prior covariance is all zeros.
  • The confidence range counts off-diagonal covariance terms once instead of twice, and is about 1 SD, not 95%.
  • Loading-dose rounding keeps the last option that beats round-up, not the best of three (dosageregimen.cpp:243-247).
  • route_information has no try, so an unknown drug or route aborts the calling Node process (pklibraryjs.cpp:3148-3156).
  • Tacrolimus auto-selection can return a disabled liver model.
  • The three-compartment closed form returns 0. Kim 2024 avoids it only because it always adds a CL time adjustment, which turns the closed form off (threecompartment.cpp:151, 160).
  • To check: closed-form predict_auc ignores num_doses and the starting level; LinearModel::amounts_at_time ignores salt and F, which matters for IV aminophylline (salt 0.79); LinearPK divides by infusion time.

Engineering debt

  • Blocking calls. No export is asynchronous, so a fit that runs up to 20 s blocks the calling service's event loop. Analytics works around this with worker threads.
  • Thread safety. Logger::times is a static map, which would race across threads.
  • Model ownership. Drug owns a raw const Model*. Calling set_model twice leaks the first model. Single-model drugs ignore the model name.
  • Fixed-size arrays. Covariance and pivot arrays are 11 × 11, which caps a fit at 10 parameters.
  • Hidden state changes. predict_level and fit() modify their object, so a fitting object can't be reused safely.
  • Build hazards. The TESTING macro changes access specifiers, so classes differ between the test build and the library (a one-definition-rule hazard). FRIEND_TEST sits in production headers, and a "Hello World" main.cpp is compiled into the library.
  • Dead code. Unselectable models, model.deprecated.cpp, seven .disabled Boost simulators, runtime_test, and a friend declaration for a ceftazidime class that no longer exists.
  • Loose conventions. Units are plain doubles with correction factors applied by hand. -1 means "not set" throughout. to_route matches display strings by substring.
  • Stale docs. The README says Node 16 and npm; the package needs Node 24 and pnpm.
