PreciseRx-Shared-JS

Shared Node code for Main, Analytics and Databridge: Cognito token verification, token pairing, cookie parsing, logging, error classes and AWS SDK adapters. It is compiled twice with plain tsc, once to ESM and once to CommonJS, and published to GitHub Packages.

  • Publishing. make publish bumps the version, pushes a stable/v… branch and publishes. The branch push triggers a second publish, which fails as expected. Tags stop at v1.10.0, so the stable/v* branches are the real release record.
  • Tests. pnpm test runs 13 Jest files with a 55% line-coverage threshold. The Cognito and SQS wrappers and the factories are untested.
  • Error handling risks. The Cognito wrapper turns its own ApplicationErrors, and any unlisted Cognito exception, into a generic 500. Persistent throttling returns null instead of throwing.
  • Local development. rebuild-watch runs two tsc -w builds side by side. The umbrella's link-preciserx-shared-js target uses it.

PreciseRx-Shared-Python

A Python copy of the Shared-JS error classes, plus a Flask error handler. It isn't published to any package index; consumers install it straight from GitHub by git ref. It has no tests and an empty README.

  • Different refs and package names. Database installs tag v1.0.0 and imports PreciseRxShared. GenAI main pins a deleted branch and imports the lowercase preciserxshared. The only difference between the two is the folder rename.
  • Broken module. http/validate_parameters.py cannot be imported, because it uses an absolute errors import that doesn't exist once the package is installed.
  • Duplicate classes. errors/constants.py defines a second copy of every error class. Catching one copy won't catch the other.
  • Missing dependencies. Flask and Werkzeug are imported but not declared.
  • Message drift. Messages differ from Shared-JS; for example, "authorization failed" here versus "authentication failed" there.
