Sign-in, sessions and roles

Every service authenticates the same way. The browser holds Cognito tokens in cookies. Each service verifies both tokens itself on every request, checks that the two tokens belong to one user, checks a shared revocation flag, then reads roles from the id token. No service trusts another service's check.

PieceHow it works
Cookiesaccess_token, id_token and refresh_token are HttpOnly, Secure and SameSite=Strict, scoped to PPK_PARENT_DOMAIN. Main sets them on sign-in; Databridge sets them after an EHR launch. There is no CSRF token; the design relies on SameSite=Strict.
User poolsSix: Email (the main PrecisePK pool), SSO, Epic, Oracle Health, Sentri7 V1 and Sentri7 V2. The pool is chosen by the token's issuer. GenAI main checks five.
VerificationNode services use Shared-JS createCognitoAuth (aws-jwt-verify). Database uses python-jose with a JWKS cache and also checks the app client. GenAI has its own weaker check.
Token pairingThe access and id tokens must share sub and iss, and in Database also the app client (RX-3606, September 2026). Without this, one user's access token could carry another user's id token, and roles are read from the id token.
RolesThe id token's cognito:roles claim holds IAM role ARNs. Each service compares them with PPK_ADMIN_ROLE, PPK_USER_ROLE and PPK_IAM_ROLE. The analytics and multi-site admin roles are required at boot but not enforced anywhere. cognito:groups is never read.
RefreshThe frontend calls POST /main/v1/auth/tokens. Main returns 204 while both tokens have more than 5 minutes left, and otherwise refreshes whichever expires first (RX-3625).
Frontend gatewithRole redirects to /403 only if the privilege check rejects. The request wrapper resolves null on a 403, so the redirect never happens for HTTP errors, and the page shell renders. The backend is the only real gate. (PreciseRx-Web/src/hooks/withRole.tsx:19-44; AxiosErrorHandlers.ts:75-77)

Revocation

Tenancy: institutions and sites

  • Institution. The id token's custom:license_name leads to the license, then to the institution ID, and that ID is the MySQL schema name. One MySQL credential can reach every schema, so isolation between institutions is enforced only in application code. It holds only if users cannot edit their own custom:license_name, which is a Cognito app-client setting that isn't in these repos.
  • Site. Multi-site institutions divide users and cases by site through Cognito groups of type site. Database does not restrict reads by site: site filters come from the caller, and cases load by number alone. Main's IAM routes check that the target user shares the caller's license.
  • Analytics sockets. Rooms are named by the client, and finished jobs are currently broadcast across all institutions (Analytics).

Logging and audit

The organization's baseline requires every privileged action to be audit-logged. Today, only Database writes an audit trail, and only for a subset of case actions. Everything else leaves at most one access-log line.

ActionAudit recordWhere
Load, create, update, autosave, archive or delete a caseYes: an edithistory_web row. The delete row can fail silently.Database

LLM prompts and generated SQLNoGenAI

Where PHI or secrets can reach logs

  • Access logs record full URLs, including query strings. That covers patient search terms in Database, case numbers in Analytics, and OAuth codes and the Epic launch token in Databridge.
  • In Main, Joi validation messages can include the rejected value next to the username and license.
  • PK-Library writes exception text to stderr, outside the structured logger.
  • The Analytics worker logs case numbers, serum IDs and predicted concentrations.
  • Main's /logs/errors and /logs/forms forward arbitrary client objects and the user's email to a Datadog workflow, with no rate limit.
  • Database logs the whole JWT when it sees an unknown issuer.

Build, deploy and CI

GitHub Actions runs unit tests on pull requests. Jenkins, triggered by hand on arm64 agents, builds backend images and pushes them to Docker Hub, tagged with the last segment of the branch name. The step that deploys those images to ECS is defined outside every repo covered here.

Production network path, from code comments in Main, Analytics and Database: WAF → API Gateway (regional REST) → VPC Link → internal ALB → ECS. Service-to-service calls go through the internal ALB with an x-api-version header (RX-3236). Node serves plain HTTP on 8080, so whether the last hop uses TLS depends on the infrastructure, which isn't visible here.

Dependency hygiene is the same across the Node repos: pnpm 11 with a 72-hour minimum release age, integrity checks, an allowlist of packages that may run install scripts, and daily Dependabot updates.
